### 2026-05-24 Live TUI Information-Presentation Audit To Preserve

Documentation-only note: do not treat the following as fixed just because tests pass or backend metadata exists. These are observed product/UX gaps from live GACT TUI use and should be solved deliberately, with screenshots or equivalent visual review before claiming release readiness.

- [ ] Information menus are still too shallow. Skills, tools, MCPs, agent info, and related inspector menus must convey full useful metadata, not only a one-line label/description. Pressing Enter on a row should drill into a detail view rather than close the menu or do nothing. Details should include prompt/source, parameters, owning agent, child agents, tools, MCP servers, skills, model/provider assignment, runtime status, memory/context summary, upstream/downstream relationships, errors, and artifacts where available.
- [ ] Skill and tool views need real detail semantics. The skill menu scrolls, but descriptions are truncated to one line and Enter does not reliably expose the full skill. Tool views should similarly expose schema, tags, owning experts, permission/risk class, provider/MCP source, examples, last call evidence, and errors.
- [ ] Agent hierarchy is not yet presented as an inspectable graph. The user should be able to open a top-level agent and see child experts, tier-3 experts, nanoagents, accessible skills, and accessible tools. Example target: Main agent routes to Data/Analysis/Visualization/Utility; Data shows NDP and other data-provider children; Analysis shows SAC/format children. This should be a continuous wiki-style navigation system, not a flat list of every skill/agent.
- [ ] The current Agent tab/list is visually noisy and semantically unclear. It mixes primary agents, skills, and source-command skills in one long list, uses unclear labels such as `[prompt]`, and does not make the main agent versus child experts versus skills obvious. Selection should show stable details, not just change row styling.
- [ ] The live conversation can still make a multi-stage workflow look like a single final route. In the seismic/NDP demo, the user prompt begins with data discovery but the conversation can appear as `visualization` only. The presentation layer must make the actual execution chain visible: orchestrator decision, Data handoff, NDP child work, staging/download if any, Analysis/SAC work, Visualization work, final synthesis.
- [ ] Child sessions and nanoagents need stronger explanation in the sidebar and detail panes. Indented entries should clearly say whether they are child sessions, nanoagents, skill agents, or subagents; show parent session, spawned-by turn, owning expert, provider/model, tool count, status, runtime duration, and artifacts; and let the user jump back to the parent.
- [ ] Tool rendering remains a release-risk area for real demos. Large NDP results and similar JSON-heavy outputs should be summarized inline as human rows/cards, but raw inputs/results must remain expandable. Long URLs, escaped HTML/unicode, nested JSON, and continuation gutters should not dominate the transcript or break borders.
- [ ] Tool call ordering and evidence provenance must be unambiguous. The transcript should show: route/handoff, tool call request, tool result, then model synthesis. It should be clear whether each displayed item is a live event, backend evidence, metadata promoted from a completed turn, or assistant text. No assistant claim of tool use should be trusted unless the actual tool evidence is visible.
- [ ] Expand/detail views should be usable for all evidence rows. Short tool calls, route decisions, handoffs, skills, agents, and MCP rows should still open details. Detail modals should be sized appropriately, scrollable, and should not waste half the screen with narrow content.
- [ ] Conversation scrolling is still suspect in long tool-heavy transcripts. The selected row/cursor can move while visible text does not reliably follow, including wheel, arrows, PageDown, End/`G`, and sticky-bottom cases. The user must be able to scroll all the way to the latest messages and see the last lines without clipping.
- [ ] Line wrapping and border integrity still need visual proof. The observed transcript showed continuation text crossing the bottom border. Every pane must clamp rendered width after styling, including wide Unicode, JSON, long URLs, provider status strings, and tool outputs.
- [ ] Sidebar scale is not solved. Stress runs can create hundreds of sessions and child sessions. The UI needs grouping, collapse/expand, filters for current workflow/errors/children, and useful counts. A flat list with `386 more` is not enough for real benchmark sessions.
- [ ] Session persistence semantics need a product decision. Deleting and recreating an agent can show old session names without full conversation content. CLIO should own enough session storage to restore names, transcripts, child relationships, tool evidence, artifacts, and metadata consistently across backend restarts or agent redeploys, or the UI must clearly mark partial/stale session records.
- [ ] Child/nanoagent session mutability needs a product decision. The likely default should be read-only materialized evidence sessions, with an explicit config/advanced setting if users should be allowed to continue chatting inside a nanoagent transcript.
- [ ] The top bar needs clearer semantics. Replace or explain opaque fields such as `ws: default`, `workspace: default`, `routing: auto`, `agent: default`, raw backend URL, and duplicate model indicators. Prefer showing agent name/type such as `myclio (clio)`, actual workspace path or alias, active provider/model, routing mode explanation, and connection state.
- [ ] The bottom bar should be contextual. Current guidance repeats the same commands for sidebar/conversation/input focus. It should show focus-specific actions: sidebar delete/rename/archive/select/filter; conversation expand/detail/copy/jump; input newline/send/command history; global settings/help/quit. `mem 25%` is unclear without a detail command explaining context/memory usage.
- [ ] Provider/model switching remains a stability and clarity risk. Observed failures included SSE connection canceled errors, slow or blocking Save and Connect, session model override errors, and model/provider swaps that affected the next message unexpectedly. Applying provider changes should be asynchronous where possible, visible as a pending state, and should not freeze the backend or hide failure status.
- [ ] Provider selector readiness/status should reflect real usability. ALCF/Argonne should not show `Globus login required` when the token is valid for model listing and inference. Readiness should use the most polite reliable validation endpoint and should clearly distinguish no token, expired token, valid token but failed inference, provider unreachable, catalog unavailable, and model unavailable.
- [ ] Provider selector UX still needs release-grade review. Preserve previous concerns: alphabetic/filterable providers and models; disabled/unreachable providers visible but clearly marked; no stale catalog plus static fake-looking model list at the same time; API key entry only when relevant; long status/API base strings wrapped; provider descriptions not cut off; model details separated from editable settings; context length versus max output clearly explained.
- [ ] Local coding CLI provider catalogs must be honest. Claude Code, Codex, Gemini, and similar CLIs should use static editable candidate catalogs unless the CLI exposes a real noninteractive model-list command. Do not treat API model lists, current model, account entitlements, or interactive pickers as the same thing.
- [ ] Localization is still far from complete. Menus, exit screen, help/options text and descriptions, window labels, sidebar section labels, conversation placeholders, provider descriptions, model details, status strings, inspector/detail views, tool labels, and error messages need locale keys. Adding a new language should be mostly adding a locale file plus registry/factory wiring. Include Spanish, Japanese/non-Latin, and Greek visual coverage, with Unicode-width tests for dense panes.
- [ ] Installation/path integration is not release-polished. `gact` disappeared from PATH on the user machine, and `gact agent deploy clio myclio` could not find `clio-agent-gact` without install detection, `CLIO_AGENT_SRC`, or `--bin`. The release path should make the current built `gact.exe` and CLIO adapter discoverable without stale copied binaries.
- [ ] The GACT agent list should expose start time and operational metadata. `gact agent list` currently shows name, kind, host/port, PID, alive, and cwd, but should also show when the adapter was started and possibly provider/model/workspace when available.
- [ ] VHS/screenshot infrastructure still needs a stable path. The emulator server should be built/reused from a stable repo path to avoid repeated Windows firewall prompts from temp `emulator-server.exe` paths. Screenshots should be used as design review artifacts, not merely proof that a command ran.
