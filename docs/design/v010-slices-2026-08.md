# v0.10 Program — Full Planning Pass (issue-tree-ready)

## Context

The v0.10 program (docs/design/v010-program-2026-08.md on develop, `1c8e39fd`) integrates
four streams into one coherent system: MCP 2026-07-28 compliance, clio-relay federation
(agents AND scientific applications), the mcp_ui_sciences interaction semantics, and the
Session v3 UI prototype — across iowarp/clio-agent and iowarp/gact-tui. All owner decisions
are closed (D1 multi-connection client/no hub; D2 shared schema package with generated TS
types; D3 Codex workhorse via codex-plugin-cc, verified live). This planning pass produces
the COMPLETE slice tree so that plan approval = mint every issue (umbrella + 5 phase parents
+ slices, cross-repo) and start P0 immediately.

**Goal state after approval:** issue tree live in both repos (+ relay-side asks), each slice
issue carrying: scope, acceptance (verifiable), failing-first test intent, deletions,
dependencies, size (S/M/L), lane (codex/claude/either). Execution starts with P0.

## Execution model (locked, applies to every slice)

- One slice = one issue = one branch = one PR; failing-first regression tests; no silent
  fallbacks (typed reasons); deletions land with replacements.
- **Fable (me): orchestration, all merges, final review of every diff, gate verdicts.**
  Claude tokens are preserved for this — implementation is delegated wherever possible.
- **Codex (gpt-5.6-sol default, via the verified codex-plugin-cc runtime): default
  implementer** for well-specified slices — `task --write` per slice in its own worktree,
  `--background` for parallel lanes (≤2-3 concurrent; one shared subscription meter).
- **Claude workflows (opus/sonnet/haiku by difficulty)**: design-heavy slices, wide
  mechanical fan-outs (sonnet/haiku), and all adversarial reviews of Codex diffs.
- **Cross-vendor review both directions**: Codex diffs → Claude adversarial review;
  Claude diffs → `/codex:adversarial-review`. Review-gate stays manual (explicit calls).
- Phase boundaries are hard gates (unit/CI + the phase's live gate) before the next phase's
  slices open. Visual harness gates P4 surfaces incrementally once it exists.
