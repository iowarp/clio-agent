| FX2-D1 | **A server declares its path arguments in the tool definition's `_meta["ai.iowarp.clio/paths"]`**: per argument, `machine` (`local`, `remote` with an optional display `host`, or `none`) and `access` (`read` or `write`). It is the tool definition, not a result, because provenance and the sandbox note need it for failed calls too. The shape and what CLIO does with each value are in [the contracts](../mcp-apps-contracts.md#a-tools-path-arguments-owner-fix2). A malformed declaration is ignored with the log reason `path_declaration_invalid`. No service name is in Python (rule 3). | H3 | `clio_agent/tools/tool_path_contract.py`; `tests/test_gact/test_declared_tool_paths.py` | done |
| FX2-D2 | **The execution boundary binds the called tool's declaration for the call** (`tool_path_contract.bind_call`, a context variable keyed by the tool name), so the observer's provenance and sandbox readers ask by name and never reach for an executor (which could build one). The bind replaces the definition lookup already on the grounding line, so `tools/execution.py` stays at 986 lines. | H3, H5; ratchet | `test_a_successful_remote_open_is_not_shown_degraded` (red with the bind removed) | done |
| FX2-D3 | **A declared remote read is a provenance input, not a warning.** On success it is one `used` edge, `remote:<host>:<path>` (`remote:<path>` without a host), evidence `schema-arg`, note `remote_input_not_observed`; nothing is resolved, read or hashed here, and a relative remote path never matches a local workspace file. The transcript metadata gets no `provenance_warnings`, so the tool row keeps the server's status. Declared `none`, local writes and remote writes leave the input scan. Declared local reads join the existing external-input contract (`external:<path>`, `external_input_not_hashed`). A remote input is unpinned, so the replay contract stays `re-runnable` with `inputs_unpinned`. | H3 | `gact/artifacts/declared_path_edges.py`, `external_inputs.py`, `transform_edges.py` (790 lines, cap 800) | done |
| FX2-D4 | **The sandbox note on a confined stdio server's failed call is structural.** It needs a confined child that served the call (`resolve_serving_child_id`) and a local write target, from the designated output args (`output_path`, `out`, …) or the declared `local` `write` args, outside the recomputed fleet territory and writable by the person. It is still hedged to `possible` and names the folder. The error text is never read, on either path: the raised error (`boundary_error_note(name, args)`) and the `isError` result (`_served_call_boundary`). Declared local writes also feed the designated-path policy violations, and the served diagnosis no longer mints its own `result_errno` violation for the same path. | H5; superseding principles 1 and 2 | `runtime/sandbox_diagnosis.diagnose_write_targets`, `gact/artifacts/violations.py`; `test_sandbox_b2.py`, `test_boundary_seams.py` | done |
| FX2-D5 | **Recall given up, on purpose.** A confined server that fails writing a local path its arguments do not name (its own cache, say) no longer gets the hedged note. The shell and `run_code` seams are unchanged: their own `SandboxResult` says the command ran under the fence, and they still read stderr for the denied path (a path-less denial there still gets the hedged note). | H5 | — | done |
| FX2-D6 | **The ParaView server computes its declaration when it lists its tools**: `local` with no address, `remote` with the SSH host otherwise. `open_view.path` is `read`; `export_artifact.path` and `export_scene.path` are `write`. CLIO restarts the server when the address changes, so the listing names the current machine. | H3 | clio-kit `mcp-servers/paraview`: `path_arguments`; `test_path_arguments_are_declared_where_paraview_runs` | done |
