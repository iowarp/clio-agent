| ENV3 | Container egress. Containers on a Docker bridge reach the internet directly (TCP to pypi.org:443, conda.anaconda.org, github.com); TLS is re-terminated by the session's egress like the host's, so a container needs only the session CA bundle (`$SSL_CERT_FILE`, here `/root/.ccr/ca-bundle.crt`): without it curl fails with "self-signed certificate in certificate chain", with it pypi.org answers 200. The host's agent proxy on 127.0.0.1:34197 is not reachable from a bridge (connection refused at 172.17.0.1:34197) and is not needed. So `login` gets no proxy: `cluster.sh up` mounts the CA read-only at `/etc/clio-pv/extra-ca.crt`, and the entrypoint adds it to the system store and sets `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `PIP_CERT` in `/etc/environment` (read by pam_env for SSH sessions). The build passes the same file as a BuildKit secret (`--secret id=extra_ca`), never into a layer. A network that does need a proxy sets `CLIO_PV_CLUSTER_HTTPS_PROXY` (written to login's `/etc/environment`) | `docker run --rm -v $SSL_CERT_FILE:/ca.crt:ro debian:bookworm-slim … curl --cacert /ca.crt https://pypi.org/simple/pip/` → 200, without `--cacert` → error 60; `/dev/tcp/172.17.0.1/34197` → refused | done |
| ENV4 | DNS in the session's Docker is occasionally flaky: sshd on `login` failed to resolve the node alias about 1 in 12 jumps ("channel 0: open failed: connect failed: Temporary failure in name resolution"), and `login` could not resolve pypi.org in the first seconds after start.
