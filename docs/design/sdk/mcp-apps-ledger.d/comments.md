# Ledger fragment: `comments` stream (the agent looks at an app; comments on app views)

Rows use the main ledger's tables. The design is the plan's addendum "The agent looks at an app; comments on app views" (`mcp-apps-surfaces-plan.md`); the wire shapes are `mcp-apps-contracts.md`, "Looking at a view and comments on it". Branch `ws/comments` in clio-agent and gact-tui.

The person's ask: "where are my comment semantics? so I can discuss visually with the agent", about app views (ParaView's 3D view in a tab, Burette's Mol*, any app). Re-scoped by the integrator: first a generic capability for the agent to look at a view on its own, then human comments built on the same snapshot and context.

## Decisions

| CM1 | `look_at_view(view)`: a native tool (`gact/mcp_app_look.py`), claimed deferred by the core plugin (`tools/runtime.py`), withheld with `model_lacks_image_input` like `view_image`. It picks a live view by title, server, tool or id (the only one, or the only one on screen, when `view` is empty) and works like an app tool call (MA13): transient session event `mcp_app_look` `{call_id, max_side: 1568}` to the surface holding the view, snapshot posted to `POST …/looks/{call_id}`, no timeout (rule 6), a cancel ends it, a closing app settles it as `mcp_app_view_closed`. `PUT …/shown {holder, shown}` says which surface holds a view (an older mount's unload never hides a newer one; showing re-publishes waiting looks), so a view no surface holds is refused at once (`mcp_app_view_not_shown`, naming the opening tool and how to show it). The result is a `clio.workspace_image.v1` descriptor: the model gets the native image part, then `model_text` (identity, the view's last report from `mcp_app_context` as readable lines, what the snapshot could not paint) through one added branch in `agents/recorded_media.py`; the PNG is kept as a session snapshot (history) and an artifact (transcript link). Presentation `mcp_app_look_presentation.present`: "Look at view" on the view's title, the image link, the report, the gaps; refusals are failed rows with the reason and the open views. The app-context block (`clio.reminder.mcp_app_context`) now covers every view on screen and says `look_at_view` can see it | Integrator re-scope; plan rule 6, MA8, MA9, MA13 | `tests/test_gact/test_mcp_app_look.py` (6 tests) | tests only |
| CM2 | The pixels come from CLIO's own outer sandbox document, not the view and not a server re-render. The view frame is on its app's sandbox origin with `allow-same-origin`, so the sandbox document is same-origin with the view and with frames the view nests from that origin (trame through the service route). It answers `clio/view-snapshot` itself (`gact/mcp_app_snapshot_script.py`, embedded in `_SANDBOX_DOCUMENT`); the view never receives it. It paints backgrounds, visible `canvas`/`img`/`video`/`svg` (svg with computed presentation styles), then one-line HTML text, clipped per frame. A WebGL canvas with `preserveDrawingBuffer: false` reads blank after compositing (measured: `drawImage`, `createImageBitmap` and `toDataURL` all transparent in headless Chromium 1243), so during a snapshot its context's draw calls are wrapped, the view frame shrinks 1 px for two frames, and the canvas is copied in a microtask after the app's drawing task; then the wrappers are removed. Probe: a nested-frame vtk-like on-demand WebGL canvas plus a 2D canvas and an `h1` came out complete in 67 ms. Mol* keeps its buffer (`DisablePreserveDrawingBuffer` defaults off in Burette's bundle); trame-vtk sets `preserveDrawingBuffer:!1`. Typed gaps: `frame_cross_origin`, `webgl_frame_not_redrawn`, `cross_origin_pixels`, `not_drawable`, `wrapped_text_not_drawn`; refusals `view_not_readable`, `view_not_laid_out`, `snapshot_tainted`, `snapshot_failed` | Integrator ("decide and record"); spec draft lists screenshot APIs as future work and names host capture of raw HTML (`apps.mdx` lines 2411, 2460); plan rule 4 (no viewer library; the view's DOM is read only by CLIO's own sandbox document during a snapshot, never edited) | `scratchpad` probe (`capture.js`, `probe3.mjs`); `test_the_sandbox_document_answers_snapshots_itself` | tests only |
| CM2-D1 | No automatic "better path": CLIO does not call a server's image tool (ParaView's `capture`) in place of the snapshot. Which tool renders what, with which arguments, is the server's knowledge, not data CLIO holds, and the snapshot is what the person sees; the agent may still call such a tool itself (model decides). A connector-entry field naming a render tool was considered and left out: it would be a contract change to `connector.schema.json` for one server | Superseding principle 1; plan rule 3 | — | done |
| CM3 | Comments on app views. `McpAppSurface` takes `comments`; the card, the `mcp-app` tab and `clio.mcp-app.v1` set it, so every frame has the one Comments icon (`FrameCommentsIcon`) in its header. `comments/mcp-app-comments.tsx` runs one `CommentSessionProvider` (region-only, destination `attachment`, surface kind `mcp-app`) with `McpAppRegionLayer` over the frame: a drag marks a region; a click marks a point (`CommentRegionLayer.onPoint`, a 64 px box centred on it, `source.point`). Each mark takes the CM2 snapshot at 2x when it is made and copies the context the view last reported (`onModelContext`) into `anchor.source.context`; a refused snapshot is `source.snapshot_refused {reason, message}` and a note on the mark. The send attaches the overview (newest snapshot, every mark drawn and labelled, at most 1568 px) and a crop per mark (`mcp-app-comment-images.ts`). Server: `documents/app_view_comments.py`, registered for kind `mcp-app` in `comment_attachments.render_attachment`, renders per mark the view's identity, the box in percent and pixels, the point, the view's report at that moment (not repeated when shared; the session's stored report when the mark carries none, said so), and typed notes; no anchor JSON. Marks stay pinned while the session is open | Comments plan rules 1 to 3; addendum A sections 1 to 3 | `tests/test_gact/test_app_view_comments.py` (3 tests); `mcp-app-look.test.ts` (3 tests) | tests only |
| CM4 | Comments stay on what the screen shows (comments plan, out of scope: camera pose, time step). A mark carries the view's report at that moment as context only; the view is not driven back to it | Comments plan "Out of scope" | — | done |
