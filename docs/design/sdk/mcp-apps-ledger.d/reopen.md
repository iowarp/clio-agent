# Ledger fragment: `reopen` stream (MA18, MA19)

Rows for [mcp-apps-ledger.md](../mcp-apps-ledger.md), in its tables. Plan: [mcp-apps-surfaces-plan.md](../mcp-apps-surfaces-plan.md), "Design: reopening". Contract: [mcp-apps-contracts.md](../mcp-apps-contracts.md), "Saved call and reopening".

## Facts

| ID | Fact | Evidence | Status |
| --- | --- | --- | --- |
| RO-F1 | The clio-core path for MA18 is the session's own record: `Session.metadata["mcp_app_calls"]`, keyed by app instance id, written with `SessionStore.update(sid, metadata_patch=…)`. A session is one clio-core record (`gact/session_records.py`, bound to the process ARC store), so the saved calls survive a CLIO restart and no new store is added. `merge_session_metadata` merges top-level keys shallowly, so `gact/mcp_app_calls.py` reads, changes and writes the whole map under one lock. | `gact/sessions.py` module docstring and `update`; `gact/message_marks.py::merge_session_metadata` | static |
| RO-F2 | Session metadata is sent to the client in full (`Session.to_wire`) and a client may patch it (`PATCH /v1/sessions/{sid}`). A saved call therefore holds only `{server, tool, arguments, display_mode, resource_uri, label, saved_at[, reopened_from, unsaved_reason]}`: the arguments are those the transcript already shows for the call. The private result and the view's HTML stay on the in-memory registry record. A patched entry can only replay a tool that still declares a `ui://` view, under the session's permission rules (RO-D4). | `gact/sessions.py::Session.to_wire`; `gact/routes/sessions.py`; `test_opening_call_is_saved_without_private_result` | static, tests only |
| RO-F3 | A view's `tools/call` route and the replay use the same path: `_run_bound` runs `SyncMCPToolExecutor.call_tool_result` in the session's tool context, which applies the permission gate, the tool observer and the MCP App observer exactly as for an agent's call (`tools/execution.py::_call_tool_inner`). Outside a turn the gate's `ask` publishes the ordinary permission card in the conversation. | `gact/mcp_apps.py::_run_bound`; `tools/execution.py::_call_tool_inner` | static |
| RO-F4 | Uses of `McpAppHistoryLine` after this stream: the fallback in `conversation-message-blocks.tsx` and `conversation-iteration-detail.tsx` when there is no repository or session, and `McpAppSurface`'s ended state when no `endedFallback` is given. Every transcript card with a repository now renders `McpAppCard` (`mcp-app-reopen.tsx`), whose closed state is `McpAppReopenLine`. `useActiveMcpAppId` and `closeMcpApp` are unchanged here (the `host` stream replaces them). | `grep -rn McpAppHistoryLine web/src` | static |

## Decisions

| ID | Decision | Source | Evidence | Status |
| --- | --- | --- | --- | --- |
| RO-D1 | MA18 lives in a new owner module, `gact/mcp_app_calls.py`. The MCP App observer calls `record_opening_call` for every admitted view (one line in `mcp_apps.py`), and the module registers its own routes from `mcp_apps.register_mcp_app_routes`. `tool` is the bare tool name (the executor name without the `<server>_` prefix), `label` the tool's `title` or a readable form of its name. | MA18; contracts "Saved call and reopening" | `tests/test_gact/test_mcp_app_calls.py` | tests only |
| RO-D2 | `POST /v1/sessions/{sid}/mcp-apps/reopen {app_instance_id}` answers 200 with `{part, saved_call}` on success and 200 with `{error: {reason, detail}, saved_call}` on a failed replay, so the card always has the saved call to show. An unknown session is 404 and a missing `app_instance_id` is 422. **Contract change:** success also returns `saved_call` (the new view's own entry). | MA19; contracts | `test_reopen_replays_saved_call_and_returns_fresh_part`, `test_no_saved_call_and_unknown_session` | tests only |
| RO-D3 | Typed reopen reasons: `no_saved_call`, `arguments_not_saved`, `tool_unavailable`, `tool_has_no_view`, `permission_denied`, `call_failed`, `tool_error`, `view_not_opened` (`REOPEN_REASONS`). Each failure is also written to the stream-audit sink (`mcp_app_reopen_failed`) and the log; a success writes `mcp_app_reopened`. The card offers Retry for every reason except `no_saved_call`, `arguments_not_saved` and `tool_has_no_view`, which need a change first. | No silent fallback | `test_failed_replay_returns_reason_and_saved_call`, `test_call_exceptions_are_typed`, `test_tool_gone_or_without_view`; web `mcp-app-reopen.test.tsx` | tests only |
| RO-D4 | The replay resolves `<server>_<tool>` in the executor's definitions and requires the definition to still carry a `ui://` resource before calling; it then calls through `_run_bound` (RO-F3). The person's click is the request, and the permission gate decides as for any call of that tool in the session; there is no separate grant for a reopen. | MA19 "follows the session's tool permission rules" | `test_call_exceptions_are_typed[permission_denied]`; live AQ25 | tests only |
| RO-D5 | A replay is admitted by the ordinary observer, which saves the new view's own call (with `reopened_from` and the saved display mode) and hands the record back through a context variable instead of appending a second `mcp_app` card to the transcript. The card that asked mounts the returned part. A view reopened in `fullscreen` is registered pinned at once. | MA19; MA6 | `test_reopen_replays_saved_call_and_returns_fresh_part` | tests only |
| RO-D6 | Arguments over 64 KiB are not kept in session metadata (it reaches the client in full); the entry is saved with `arguments: null` and `unsaved_reason: arguments_not_saved`, and reopening returns that reason without calling the tool. | No silent fallback | `test_large_arguments_are_not_saved_with_a_reason` | tests only |
| RO-D7 | `PUT …/display-mode` (the `host` stream's route) also records the mode on the saved call, so a reopen restores the tab or the card. | MA4, MA18 | `test_display_mode_route_updates_the_saved_call` | tests only |
| RO-D8 | `GET /v1/sessions/{sid}/mcp-apps/{app_id}/live?data_ref=` returns `{live}` without touching the record's idle time. A card asks it before mounting, so a view CLIO no longer holds reads as closed instead of as a failed descriptor request (a 404 in the browser). | Brief: no failed requests | `test_live_check_does_not_fail_for_a_closed_view`; core `mcp-app-reopen.test.ts` | tests only |
| RO-D9 | UI: `McpAppCard` shows the card's view while CLIO holds it, else `McpAppReopenLine` ("View closed", Reopen). A successful reopen mounts the fresh view in the same card and is remembered per browser (`localStorage` key `clio.mcp-app.reopened.v1`), so a reload remounts it while CLIO still holds it. A failure shows the reason, the saved call ("Open a board from boards", "With title: \"Q3 roadmap\", count: 4") and Retry. Inline cards are never replayed automatically after a restart; only restored tabs are (plan default). | MA19 | `web/src/components/clio/mcp-app-reopen.test.tsx` | tests only |
| RO-D10 | Fixture: `tests/fixtures/app_reopen_server.py`, an ext-apps-style stdio server with `open_board(title, count)` opening `ui://boards/view`. `APP_REOPEN_CALL_LOG` records every call (the evidence a replay called the tool again with the saved arguments); while `APP_REOPEN_FAIL_FILE` exists the tool fails, so a replay can be made to fail and then retried. Registered on the stack as the user connection `boards` (`PUT /v1/mcp/configuration/boards`, `always_load: true`). | AQ25, AQ26 | step file `scripts/cloud/checks/apps/reopen_card.mjs` | done |
