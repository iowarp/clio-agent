## Found outside this change

Recorded, not fixed here:

- Every native builtin tool call is recorded twice in `metadata.tools_called` (the live observer keeps the boundary's `{"kwargs": …}`, so it never merges with the trajectory row). Seen on `recall_context`; MCP tools are recorded once. `tool_instrumentation.py` / `tool_observer.py`.
- Two of 80 assistant text parts on this run began with a leaked token (`_tool_calls`, `_memory`) before the real text, both on memory-writing turns with `claude_code`/`claude-haiku-5-5`; the turns recovered.
- The browser's GitHub releases check (`web/src/lib/github-releases.ts`) hits the unauthenticated rate limit in a shared environment (console `403 (rate limit exceeded)`).
- Full-suite workers grow to about 5.6 GB, and on a 16 GB machine with 3 workers one or two are OOM-killed per run (xdist replaces them). The same 150 `tests/test_gact` files in one process peak at 6060 MB on the base `7b80019` and 6258 MB on this branch, with 14 more tests, so the growth is the base's.
- Once in about ten live turns after the base merge, the conversation view stopped after a tool call: the answer's final text and **Done** did not appear until a reload (`sess_ec94d509d6eb`, memory off, text → `query_tasks` → text). The server transcript was complete. Four turns of the same shape and the same check rerun rendered live, so the cause is not identified.
