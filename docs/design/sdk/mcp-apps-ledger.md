Status vocabulary (as in the [acceptance ledger](acceptance-ledger.md)):

- `passed (live)`: exercised against a running CLIO, with the sessions, commands and screenshots that were read.
- `tests only`: covered by the named tests and not exercised live.
- `static`: checked by reading the tree.
- `done`: a recorded decision with no behaviour of its own.
- `superseded`: replaced by the row it points to; kept so the history is honest.
- `open`, or `blocked` with the reason.

Live scenarios run on Sonnet 5.5 through the `claude_code` provider. **The plain-request rule:** a prompt that names the tool, its arguments or the steps verifies the mechanism only, and is recorded as "mechanism verified with a tool-directed prompt; not evidence of agent judgement". Only a plain request counts as evidence of the agent's choices. Every Qualification row says which kind its prompts were.

**How this ledger was made.** The work ran as parallel streams, each on `ws/<stream>` with its own stack, then integration qualification streams on the merged code, then fix streams. Each kept its rows in a fragment; this file merges them and the fragments are deleted. Row IDs keep the stream's own prefix so they match commit messages and step files. Where a later row changed an earlier one, the earlier row is marked `superseded` with a pointer, and the current behaviour is the later row.

| CM1 | `look_at_view(view)`: a native tool (`gact/mcp_app_look.py`), deferred by the core plugin, withheld with `model_lacks_image_input` like `view_image`. It picks a live view by title, server, tool or id (the only one, or the only one on screen, when empty) and works as an app tool call: transient event `mcp_app_look {call_id, max_side: 1568}` to the surface holding the view, snapshot posted to `POST …/looks/{call_id}`, no timeout, cancel ends it, a closing app settles it as `mcp_app_view_closed`. `PUT …/shown {holder, shown}` says which mounts hold a view (a card and a tab overlap while a frame moves).
