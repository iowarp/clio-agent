CLIO web search · evaluation · 12 Nov 2026

Replacing SearXNG in CLIO

A survey of how about 40 open agents get web results, live tests of 25 no-key search and fetch paths, and a recommended design that works on first launch, has a daily allowance, and lets users pay for more when they need it.

Tests ran from a Linux cloud container on a datacenter IP on 12 Nov 2026. Vendor limits and prices were read from official pages the same day. Anything not confirmed from a primary source is marked as unverified.

Recommendation

  1. Retire the managed SearXNG. It is still common in self-hosted chat apps (Vane, Local Deep Research, Khoj, Morphic), and those apps carry hundreds of “0 results” issues. Google, Brave, Qwant and DuckDuckGo are blocking SearXNG servers right now. No coding agent uses it as a default; Hermes keeps it as an optional fallback. In my tests every SearXNG-style scraping path failed: the same engines through ddgs, and 25 of 25 public instances.
  2. Default to a keyless ring of hosted search endpoints, as Hermes and OpenCode now do: Exa, Parallel, You.com, Keenable and Firecrawl. Each worked here with no account. Rotate to the next one on a 429 and emit a typed reason each time. This is what makes search work on first launch.
  3. Add free scholarly APIs directly: arXiv, Crossref, OpenAlex, PubMed and Europe PMC. They are stable, documented and keyless or free-key. For a scientific research agent they are the highest-value sources.
  4. Use the search the user's model login already includes, when the session's provider has it: Claude Code, Codex or Gemini. The login is already there, so nothing new is created; it is one more provider in the rotation. Local and ALCF models do not have it.
  5. Deferred until funded: an IOWarp search gateway. It is the only way to offer a guaranteed daily allowance with a paid tier: an anonymous install token issued on first launch, a daily quota, and upgrades on an IOWarp account. Nous runs this pattern for Hermes. It costs roughly $0.05–$0.70 per active user per day. Until then, search is free and best-effort, and the ring is built so the gateway can be added later as one more provider.

Out of the pattern: any key a person has to go and create. That covers Tavily, Brave, Linkup, Exa and Firecrawl keys, an Ollama account and an OpenAlex key, so they are not part of the design. Vendor terms also forbid shipping one shared key inside CLIO.

This moves search out of CLIO's service layer. About 3,500 lines of source, 3,100 lines of tests, a native Windows install and a supervised process are replaced by about 500 lines of HTTP client code in the Web MCP adapter. CLIO keeps only the search settings and, if the gateway is built, the install token.

Recent fixes show where the cost lands: Windows archive paths, native Windows supervision, stopping services on clio stop, and proxy support behind the Windows fence. None of these improve search quality; they keep a metasearch server alive. SearXNG gets its results by scraping engines like DuckDuckGo, Brave, Mojeek, Qwant and Startpage, and those engines increasingly block automated clients. That is why it “fails half the time”.

Deep-research projects

SearXNG is common here, and so are its failures. It is the most common self-hosted backend: 11 of about 22 projects support it, and Vane (formerly Perplexica), Local Deep Research, Khoj and Morphic bundle it as the default in Docker Compose. Those same projects have the largest piles of “0 results” issues: 188 SearXNG issues in Vane, 136 in Local Deep Research, 38 “no results” issues in Open WebUI. The research tools themselves (GPT Researcher, LangChain open_deep_research, STORM, Tongyi, MiroThinker, dzhng/deep-research, HF ODR) all need a key by default, mostly Tavily or Serper. The upstream evidence

  • SearXNG's own tracker, Oct–Nov 2026: Google returns 403 and redirects to /sorry/ (searxng#6835). Brave suspends for “too many requests” while Google and Qwant are “access denied” (#6866). DuckDuckGo serves a CAPTCHA on every request (#6779). Qwant returns fabricated results when the server IP is blocked (#6358). Since May 2026, 95 issues report 403/429/CAPTCHA.
  • ddgs, the library inside CLIO's Web MCP adapter: as of 4 Nov 2026, every text backend returns “No results found”, because DDG answers 202, Brave answers 429, and blocked and empty pages are reported the same way (ddgs#498). That matches the 0–8% measured below.
  • The newest apps are leaving scraping: Jan, AnythingLLM and LibreChat moved to the Exa, You.com and Keenable keyless tiers. AnythingLLM's source records You.com keyless as 100 queries per IP per day. Keenable's docs say every caller on one IP shares 1,000 requests per hour.
  • Scholarly design: Local Deep Research is the model to copy. It runs per-source engines with adaptive rate tracking and lets the agent choose engines per sub-question.

Rate-limit behaviour

  • Exa keyless: 40 back-to-back sequential searches with no errors (median 0.47 s). With 10 parallel workers, 4 of 30 calls got 429 with Retry-After: 1. The error text invites the user to “create a free Exa account … No payment method required”. That is a ready-made upgrade path.
  • Firecrawl keyless cuts off after about 10 calls in a short window and points to a free-key signup.
  • Tavily keyless has a per-IP daily cap (third parties say about 30 per day; unverified). It was already spent on this shared IP. Users behind campus NAT or an HPC login node will see the same thing.
  • Not yet measured: a real deep-research run against the rotation. Each vendor was tested on its own; the rotation was not built when these tests ran, and the 20–60 searches per run figure is an estimate. The deep-research flow runs up to 8 researchers at once, which is the concurrency at which Exa returned 429s.

Model-native search through a CLIO provider

The claude CLI that CLIO's claude_code provider drives ran its built-in WebSearch here: 20 relevant ADIOS2 doc URLs in 18.8 s, billed to the subscription. CLIO currently starts that provider with allowed_tools: [], so its agents never see this tool. Native search exists only for Anthropic, OpenAI and Google accounts. It does not help LM Studio, ALCF or other OpenAI-compatible endpoints, so it cannot be the default for a model-agnostic agent. It is reasonable as an optional fast path later.

What the terms allow

  • Embedding one shared vendor key in CLIO is ruled out. Brave, Tavily, Firecrawl, Semantic Scholar and Jina all forbid sharing or disclosing a key, or hold the key owner liable for everyone's use.
  • A proxy that IOWarp operates is allowed if IOWarp is the customer, pays, and gives users its own terms. Tavily allows this explicitly. Brave requires a written end-user agreement and forbids redistributing or reselling results.
  • Caching: Brave forbids storing results beyond transient use, and Mojeek's startup plan allows one hour. ARC memory must not keep raw Brave results; storing CLIO's own summaries and fetched pages is a separate question.
  • Keyless endpoints are published by the vendors for agent use. Exa, Parallel, You.com, Firecrawl, Tavily, Keenable and TinyFish document them, and their error messages invite signup. Hermes and OpenCode both ship them on by default. Send an honest client name (User-Agent, Keenable's X-Keenable-Title) and respect Retry-After.

Will free tiers cover deep research?

A deep-research run issues about 20–60 searches and 30–100 page reads. Two runs a day plus normal agent browsing is roughly 60–170 searches and 60–250 page reads per user per day, or 1,800–5,000 searches a month.

A guaranteed daily allowance (“N deep researches per day, then pay”) needs a gateway someone operates, because keyless limits are per IP and unpublished. Cost for IOWarp at list prices: 100 searches per user per day costs $0.10 on Parallel ($1/1k), $0.40 on Exa lite, or $0.50 on Brave. Add page reads at $1/1k on Exa or Parallel. That is $0.05–$0.70 per active user per day, or about $1.5k–$21k a month for 1,000 daily users. CLIO would request the install token from the gateway on first launch, with no user step, the same way Nous gives anonymous Hermes guests free search. Paid tiers raise the quota on that token.

Recommended design

Default

Keyless ring (first launch, zero setup)

An ordered list of providers: Exa → Parallel → You.com → Keenable → Firecrawl. Pace calls to at most 2–3 concurrent per provider. On a 429, cool that provider down for Retry-After (or 60 s) and try the next. Every rotation emits a typed reason (search_provider_rate_limited, search_provider_failed) into the trace, following the no-silent-fallback rule. If the whole ring is exhausted, return a typed search_quota_exhausted error that names the upgrade, so the model and UI can say so plainly.

Always on

Scholarly sources

Call arXiv, Crossref (with mailto), OpenAlex, PubMed and Europe PMC directly, paced to their published terms. arXiv allows one request every 3 seconds; the client enforces that. Do not put them in the web rotation: they only answer literature queries, and Crossref returns fuzzy matches for anything (100% answered, 0% right source). Do not route by matching keywords in the query either, because CLIO core must not decide by keyword. Instead, let the model choose by calling web_search(..., sources="scholarly") or a literature_search tool. That call fans out to the scholarly APIs in parallel and de-duplicates by DOI or arXiv ID. The tool description tells the model to write keyword queries, since Europe PMC returned nothing for long natural-language ones.

Login

Search that comes with the model login

When the session runs on claude_code, Codex or Gemini, add that provider's built-in search as one more ring member. Today CLIO starts the Claude Code provider with allowed_tools: [], so this means allowing only its WebSearch and recording results through the same provenance path. It is automatic because the login already exists, and it is simply absent for local and ALCF models.

Fetch

Local first, hosted fallback

Keep local httpx + trafilatura/readability. On a 403 or 429, or an empty or JavaScript-only page, retry through Exa fetch, Parallel fetch, Keenable fetch or Jina Reader. Report which reader produced the text in the provenance the deep-research critic already checks.

If funded

IOWarp gateway with an automatic install token (deferred)

This is the only way to deliver a guaranteed “a couple of deep researches a day, then pay” within the pattern. On first launch CLIO registers anonymously and receives a token. The gateway calls one or two paid vendors on IOWarp's own account, which their terms allow when IOWarp is the customer, and enforces a daily quota. When the quota is used up, CLIO returns a typed search_quota_exhausted error that names the upgrade, and falls back to the keyless ring. A paid IOWarp account raises the quota. The gateway can be built after the ring ships; the ring stands on its own.

Could SearXNG run the ring for us?

Only partly. CLIO's pinned SearXNG (e8e710e) already ships a keenable engine with keyless mode. It is disabled by default, and enabling it is a settings change. Its exaapi engine needs a paid key, because it calls api.exa.ai, not the free MCP. There are no engines for Parallel, You.com or Firecrawl. The free tiers are MCP endpoints that stream JSON-RPC (Exa answers HTTP 406 if the client does not accept a stream), so SearXNG's generic json_engine cannot read them. They would need custom engine modules patched into the SearXNG install.

Its design also works against free allowances. SearXNG sends every query to every enabled engine at once, so one search spends all five vendors' allowances instead of one. It only searches, so it cannot provide the hosted-fetch fallback. It also reduces results to title, URL and snippet, which drops the 22–38k characters of excerpts these vendors return per query. And it keeps the install and supervision burden. SearXNG is worth keeping in two places only: server-side, if IOWarp builds the gateway (CLIO's existing clio_web_search backend already speaks its API), and as an optional self-hosted URL for air-gapped sites.

Where the code lives

The first proposal put the rotation in clio-kit's Web MCP adapter. The implementation instead hosts it inside the CLIO server as built-in MCP servers: one process-wide limiter for every session, questions through CLIO's own question tasks, keys straight from the credential store, and no cross-repo pin. The configuration is small:

search:
  enabled: true
  web:
    order: [keenable, exa, firecrawl, you, parallel]
    disabled: []
    auto_switch: false
  approved: []             # filled as the person approves sources
  literature:
    disabled: []
  service:
    url: ""                # a site's CLIO search service, optional
  # keys live in the credential store: search-provider:<source>

Risks and mitigations

A vendor narrows or closes its keyless tierFive independent vendors in the ring; the provider list is config, so a dead one is removed without a release. Firecrawl and Tavily already throttle hard.
Shared IPs (campus NAT, HPC login nodes, cloud) exhaust per-IP quotasObserved with Tavily here. Detect daily_cap_reached-style answers, cool down for the full Retry-After, and rely on the other ring members. The IOWarp gateway's quota is per install token, not per IP, so it is the fix for shared networks.

Offer backend: none and keep a self-hosted SearXNG URL as an optional provider for air-gapped sites; it just stops being the default.
Result quality differs between vendors, so a run can change with rotationRecord the provider for every search in the provenance log. A deep-research flow can pin one provider for the whole run (a session id), as Hermes does with _SESSION_ID.
Terms changeRe-check the vendor list each release; this report records the 12 Nov 2026 state.
The free tiers are a sales funnel, not a service promise. Each 429 message is a signup pitch, and no vendor has agreed to carry a distributed product's default trafficHermes and OpenCode set the precedent, but it is unwritten. Send an honest client name, and contact Exa, Parallel and Keenable before launch; Vane is already Exa-sponsored. Treat the ring as best-effort, and the gateway as the only guarantee.
Response formats drift. Exa's free MCP schema lists objective as required (calls without it still worked on 12 Nov), returns a text blob that must be parsed, and rejects plain JSON clientsRun a nightly canary that makes one real call per vendor, plus recorded-response tests. New outbound hostsFive search hosts and the scholarly APIs must be on the sandbox network allowlist. Compute nodes without internet access are unchanged.
Thin evidence12 queries, two rounds, one day, one IP, and a coarse domain check. Before switching the default, run a week-long canary from a residential and a campus network.

What was built

After this evaluation, the owner's decisions and an independent review (below) shaped the implementation on branch claude/nifty-mccarthy-ybiwgz:

  • No local search server. SearXNG, the managed Web Search service, its installers and the clio-kit Web Search adapter were removed; the old search.* keys are typed config_key_removed errors.
  • Built-in tools, not an external MCP. web and literature are in-process MCP servers beside fs/shell, claimed by the web and new literature plugins. Tool calls stay MCP task records, so deep research's evidence binding is unchanged, and one process-wide limiter serves every session and child session.
  • Order and questions. Web sources are tried in the person's order (default Keenable → Exa → Firecrawl → You.com → Parallel). The first query to a source asks for approval; a used-up free allowance asks once for every waiting caller: switch, switch always, add a key, or stop. These questions always go to the person, also in bypass mode, never to an agent.
  • No key needed; keys optional. Settings → Web search reorders sources, turns them on or off, adds keys (stored in the credential store) and shows status in words and today's counts. Settings can request a free OpenAlex key for the person's email. A search service URL lets a site serve search for everyone.
  • Compact results. The model sees title, URL, date and a short snippet; the full source answer is saved to payload_file. web_fetch reads locally first and uses a hosted reader only for public URLs.
  • Literature. literature_search queries OpenAlex and Crossref plus field sources from a declared table chosen by the model's field/kind; literature_lookup follows references, citations and versions. Skills web-research and literature-search carry the craft; deep research's researcher and critic got the literature tools and lost their SearXNG instructions.
  • Deferred: the IOWarp gateway (until funded), model-login search, and deep-research flow changes (scoping step, typed packets, binding researcher fetches, conditional prompt pieces), each to be A/B-tested after merge.

Research results recorded during implementation

  • Recorded responses for every API are test fixtures (tests/test_search/fixtures). From this shared cloud IP, Exa, Firecrawl, Parallel and OpenAlex were already rate-limited during capture, so their success fixtures are partial; recapture them from a normal network after merge.
  • Filters were honoured where checked: Keenable (site, published_after) and You.com (date range, excluded sites). Parallel reports a used-up free tier as JSON-RPC -32000 inside HTTP 200, so the client reads the body, not the status.
  • OpenAlex now prices by request: a single-work lookup is free, a filtered list costs $0.0001, a search $0.001, against $0.10/day per IP without a key. It also offers an agent key flow (POST /api-keys with an email, activated by one click).
  • Deep research's skills reach its researcher and critic: CLIO keeps core tools such as load_skill on subagents with a tool allowlist.

Independent review

A second model reviewed this report and the proposals. It approved the direction but not the confidence, and its findings changed the design: per-run sticky vs global order (the owner kept a global order with questions), keeping a site service URL, compact results for small models, public-URL-only hosted reading, and the elicitation routing fix so search questions never go to an agent. Its corrections to the evidence are applied above (local fetch 8/12, the unmeasured rotation, the Exa schema note).

Method and limits of this study

  • All tests ran from one datacenter IP, which many cloud sessions share. That understates scraping (ddgs, DuckDuckGo, public SearXNG), which does better on home connections but is exactly what blocks first under load. It also understates per-IP keyless quotas (Tavily, OpenAlex, Wikipedia). On a residential connection the keyless ring should do at least as well as measured here.
  • “Right source” is a coarse domain check, not a relevance judgement. The ranking is clear without it, but it is not a quality benchmark between Exa, Parallel and You.com.
  • Tiers that need a manually created key (Tavily, Brave, Linkup, Exa, Ollama, LangSearch, Serper) were not tested, because they fall outside the zero-setup pattern. Their figures come from official pricing pages read on 12 Nov 2026 and are for reference only.
  • Unverified: the published keyless limits for Exa, Parallel, You.com, Keenable and TinyFish (none publish numbers); Tavily keyless ≈30/day; the date Brave's free plan ended; You.com free API credit; Europe PMC and CORE limits.
  • Agent survey: shallow clones of each project's default branch, read 12 Nov 2026 (Hermes at commit 754855f, OpenCode v2.2.7). Research and chat apps were read from raw source files and docs; GitHub issue counts come from GitHub search the same day.
