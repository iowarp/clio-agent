# Tool presentation readability pass

The compact row, expanded result and raw technical disclosure serve different
readers. This pass keeps exact tool evidence while repairing missing meaning in
the first two levels. It does not change agent tool selection or scientific results.

## Evidence examined

- All 59 native registration sites and the registered filesystem, shell and web
  presentation adapters were inventoried. Dynamic registration sites represent
  families, so this is not a claim that there are exactly 59 runtime tools.
- The saved Alta, Tahoe and Konza native exports contain 299 calls across 21 tool
  names. Completed message Parts were joined to tool records by call ID.
- Those records include 45 results with no presentation blocks: 20 widget
  inspections, 19 widget captures, three connected-folder listings, two NDP
  searches and one Endpoint operation inventory. This count describes the saved
  presentation defects, not failed scientific operations or fresh acceptance.
- Alta's first NDP load reads the main procedure. Its second reads
  `references/discovery-and-analysis.md`. The intervening directory listing used
  the Alta workspace, exited zero and recorded empty stdout/stderr. The record
  establishes the operation and outcome, not an independent reason for the
  model's choice to run it.

## Changes

| Family | Compact result | Expanded result |
| --- | --- | --- |
| Skills | Procedure purpose, or exact reference / distinct-file count | Skill ID, purpose, exact source file links and bounded loaded content |
| NDP discovery | Query and result count | Datasets/resources or organizations, catalog context, human paging and warnings |
| NDP Endpoint operations/requests | Operation purpose and actual HTTP/capture outcome | Operation inventory or parameters, receipt, captured body and saved response |
| Execution/document runtime | Ready or missing task dependencies | Interpreter versions, actual import checks, available packages and document capabilities |
| Document preparation | Action and document | Requested pages/sheet/range, actual derivatives and outstanding review |
| Widget inspection/capture/report/deletion | Observed readiness or actual receipt | Named views, readiness/errors, real controls, captured image or saved report |
| Connected data open/write | File/folder or saved destination | Returned entries and access; write receipt distinguishes staging from source modification |
| Weather | Resolved place and forecast coverage | Conditions, units, dated forecast and source |
| Goal/loop/wait | Accepted work or waiting outcome | Objective, actual schedule and resume condition; routine limits stay technical |
| Shell | Exact command and process outcome | Working directory, recorded stdout/stderr or explicit absence, actual timeout/exit |

Existing file/diff, resource, artifact, task, todo, scheduling and web presenters
retain their dedicated contracts. Unknown third-party MCP tools still depend on
their declared standard content; this pass cannot invent semantics for arbitrary
private JSON schemas.

reads through the current NDP skill loader, explicitly labelled as component

bounded reference content, exact arguments in the technical modal, empty shell
