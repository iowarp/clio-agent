# CLIO 0.9.4.20 verification on an ALCF Aurora node

**For:** a Codex agent with a shell on an Aurora node (Linux, PBS, Intel GPUs, Apptainer; Docker is not available).

**Goal:** verify the released CLIO **0.9.4.20** (PyPI `clio-agent==0.9.4.20`; GitHub release `v0.9.4.20`, published as Latest on 2026-09-27) behaves as the release claims, from a Linux HPC node. Report what passed, what failed (with exact error text and log lines), and what could not be tested and why.

Test the **released** artifact only. Never check out source to "fix" something during verification; report it instead.

## Ground rules

- **Your own files only.** Work in your own scratch directory (e.g. `$HOME/clio-verify-0.9.4.20/` or a project scratch path). Set `CLIO_USER_DIR` to a directory inside it so nothing touches an existing CLIO install.
- **Leave nothing behind.** When you finish:
  - no CLIO server, clio-core daemon, model server or container may still run;
  - delete PBS jobs you submitted;
  - remove the scratch directory, unless the report points at logs you keep there.
  - List what you started and confirm each is gone.
- **Secrets.** Never print tokens, API keys or sign-in codes. If a step needs a sign-in you cannot do (e.g. a browser Globus login), mark it "needs the owner" and move on.
- **OpenRouter.** Use **free models only** (ids ending `:free`, or `openrouter/free`); never a paid model. A 429 means the free daily quota is spent; record it and move on.
- **Pace.** Keep heavy things one at a time: one model server, one CLIO server.

## 0. Install

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh      # if uv is missing
uv tool install --prerelease allow --with dspy==3.3.0b1 clio-agent==0.9.4.20
clio-agent --version                                  # must print 0.9.4.20
```

Record the Python version, OS release, `uname -m`, and whether the install needed anything extra (compilers, `--python` pinning, proxy settings). A compute node may have no outbound internet; if so, install on a login node and note it.

## 1. Health and doctor

```sh
export CLIO_USER_DIR=$HOME/clio-verify-0.9.4.20/user
clio-agent doctor
clio-agent serve --port 17990 &           # background; note the PID
curl -s localhost:17990/v1/health | python3 -m json.tool
```

- `overall_status` should be `ready` or `degraded`, with every degraded row carrying a plain-language reason. A raw traceback in any `reason`/`detail` is a failure.
- **clio-core (memory store):** does the daemon start on this node? If it degrades to local storage, record the typed reason exactly. A shared home plus a node-local daemon is a known sensitive area.
- `GET /v1/system/latest-release` should report the latest release (0.9.4.20), or a plain sentence saying why the check could not run (e.g. no internet). Before 0.9.4.20 this showed "Not checked" with no reason.

## 2. Provider checks (API-level; no UI needed)

For each, use `GET /v1/providers`, the provider catalog and model-list routes, and one short turn through `POST /v1/sessions` plus a message. See `GET /openapi.json` for exact shapes.

1. **ALCF inference endpoints** (the reason this runs on Aurora).
   - Does the ALCF provider list models with an existing ALCF sign-in? If no token is present, the provider must say "sign in" in a plain sentence, not a raw error.
   - If you can complete a sign-in (device or browser flow the owner approves), check that the model list appears within seconds and one turn answers.
   - 0.9.4.20 fixed discovery sending a placeholder instead of the token ("Token not active"), and a failed code paste counting as a completed sign-in. Look for `alcf sign-in: reason=` lines in the server log.
2. **OpenRouter free router:** a turn on `openrouter/free` streams an answer. 0.9.4.20 fixed "Reasoning is mandatory ... cannot be disabled (400)". The key must come from the owner through an environment variable; never print it. Skip if no key is provided.
3. **Model picked through the API survives a restart:** `PUT /v1/providers/lm` with a model, restart the server, then read it back. Under the existing precedence rule the config file now beats `CLIO_LM_PROVIDER`; confirm and note it.

## 3. Managed model servers on HPC (0.9.4.20: protected by default)

On this node, with **Apptainer** as the container runtime:

1. Deploy a managed **llama.cpp** server with a tiny GGUF model (CPU is fine). vLLM on Intel GPUs is optional; note whether the image even applies to XPU. Ollama is container-only.
2. **Protected by default:**
   - The server gets its own access key and reports "protected".
   - The key must not appear in the process command line: check with `ps -ef | grep -i llama` or `/proc/<pid>/cmdline`.
   - A request without the key must be refused.
   - CLIO's own requests succeed, with the key sent automatically.
3. Toggle **Shareable**: the key is turned off and the server reports not protected.
4. **Discovery:** CLIO lists the model with context length and capability facts from the server. Record what it reports.
5. **Uninstall** through CLIO: the container is gone, the port is closed, and there is no leftover record under `$CLIO_USER_DIR` (0.9.4.20 also cleans stale server records at startup; restart once and confirm).

## 4. Agent behavior checks

1. **Base agent tools:** the base agent now has a web fetch tool and can ask the user questions. Confirm both appear in its tool list, e.g. via `GET /v1/agents/...` or the session's agent info.
2. **Long shell output:** a command with very long output reports "full output saved" with a path, and the saved file exists.
3. **Questions from the agent:** trigger one (e.g. an ambiguous request). The question appears as a pending item on the session, answering it through the API resumes the turn, and it does not block sending another message.

## 5. Web mode

```sh
clio-agent serve --port 17990    # with CLIO_WEB_DIR pointing at the unpacked clio-web-0.9.4.20.zip from the GitHub release
```

- `GET /` returns the SPA, a deep link falls back to `index.html`, and `/v1/*` is not shadowed.
- Optional, if you can tunnel a port to a browser: the transcript renders, links open, and the sidebar lists every session, including empty ones.

## 6. Resource behavior

- While a 3-turn session runs and for 3 minutes after, sample RSS of the CLIO server and clio-core daemon every 30 s (`ps -o rss= -p <pid>`). Report peak and final.
- After the server stops, confirm no orphaned `clio`, `clio_run` or MCP-server processes remain (`pgrep -fa clio`).
