# CLIO 0.9.4.20 verification on a desktop machine (with a display)

**For:** an agent (e.g. Codex) on a machine with a real display where it can install the CLIO desktop app, drive it, and take screenshots. Windows is the primary target; macOS or Linux work too.

**Goal:** verify the released desktop **0.9.4.20** (GitHub release `v0.9.4.20`, published as Latest on 2026-09-27; it pairs with gact-tui 0.11.2.21) against everything the release claims. The headless server and HPC checks are in `v0.9.4.20-verification-aurora.md`; this document covers what needs the UI.

Test the **released** artifacts only. Never patch source during verification; report the problem instead.

## Ground rules

- **Screenshots are the evidence.** Take one for every check, open it, and judge it yourself against the expected result below. Name them `NN-short-name.png` in `~/clio-verify-desktop/shots/`.
  - A check passes only if the screenshot shows the expected result.
  - Where a state is interactive (hover, loading), capture that state.
- **Driving the app:** the desktop app is Tauri, a webview. Drive it with the OS (keyboard/mouse automation) or through the webview's DevTools protocol if available. The web client (`clio --web`, or the desktop's web mode) is acceptable for checks that are not desktop-specific.
- **Needs the owner:** anything asking for a password, Duo push, Globus login, or an API key the owner has not provided. Stop at that screen, screenshot it, and mark the check "needs the owner". Never type real credentials yourself, and never print tokens or keys.
- **OpenRouter:** free models only (`openrouter/free` or ids ending `:free`). A 429 means the free daily quota is spent; record it.
- **Clean up:** no CLIO, clio-core, model servers or containers left running on remote machines, and any Slurm allocation you made cancelled. List what you started and confirm each is gone.
- **Logs** are at `%LOCALAPPDATA%\ai.iowarp.clio.desktop\logs\backend-boot.log` on Windows. Quote relevant lines for any failure.

## 0. Install (and the update path)

1. Install **desktop 0.9.4.19** from the GitHub release `v0.9.4.19` (bundled installer for your OS).
2. In 0.9.4.19, install **Claude Code support** from the app (the provider picker or Settings; it offers an Install action). This sets up check 1.3.
3. Update **in the app** to 0.9.4.20.
   - Every stage should be visible (checking, downloading with progress, applying, restarting, reconnecting, done), and it should come back connected.
   - Screenshot each stage you can catch.
4. Confirm the version in Settings > About: desktop 0.9.4.20, CLIO 0.9.4.20.

If the in-app update fails, record it, then install 0.9.4.20 directly and continue.

## 1. Retest the failures fixed in 0.9.4.20

1. **Sidebar:** create sessions, including one you never send a message in, and two with the same title. Every session is listed, including the empty one. Same-name sessions show their start time and message count.
2. **OpenRouter free:** select OpenRouter > free in the model picker and send a short message. The answer streams, with no "Reasoning is mandatory" error. If no key is configured, the picker offers key entry; stop there and mark "needs the owner".
3. **Claude Code after the update:**
   - Support installed on 0.9.4.19 was not recorded, so it needs one more Install after this update. Do it once.
   - Then restart the app. You should see "Restoring Claude Code support after the update" at most once, and a Claude Code turn works (if the machine is signed in to Claude; otherwise "needs the owner").
   - Every later update should keep it; you can't test that until the next release, so note it as pending.
4. **Infrastructure page:** reads in plain words (for example "Docker is installed but not running"), with raw details behind "Show details". A raw diagnostic dump on the main view is a failure. Test with Docker stopped and with it running, if possible.
5. **Version panel:** both rows (CLIO desktop and CLIO) show a real check result. If a check can't run (e.g. disconnect the network briefly), it says why in words. It must not say "Up to date" while unchecked.
6. **Claude Code cost:** after a Claude Code turn, the bottom bar shows the cost the SDK reports, not $0.

## 2. ALCF (needs the owner for sign-in)

1. Open the model picker and select ALCF Metis (or another ALCF cluster listed).
2. With no sign-in, it shows **Sign in** with the verification steps. Screenshot that, then hand over to the owner. The owner signs in and pastes the code; do not do it yourself.
3. After sign-in, the model list appears within seconds, and one short turn answers.
4. If it fails, the reason is a plain sentence, and `backend-boot.log` has lines starting `alcf sign-in: reason=`. Quote them.

## 3. Items not yet checked live

Use a workspace with a CSV, an image and a PDF in it.

1. **Links:** a link in an answer opens in the system browser (ask the agent for an answer that includes a URL). Also try a link in Settings > About.
2. **View tools:** ask the agent to look at the image, then at the PDF.
   - The transcript shows a preview card: the image itself, and the PDF at the pages viewed.
   - The image card has no empty space below the image.
   - Clicking the card opens the file.
3. **Files view refresh:** with the Files view open, create or modify a file in the workspace (by the agent, or by hand). The view updates without reopening; a Refresh button is also available.
4. **Known services (Connect page):** with at least one saved CLIO service, rename it, then forget it. "+ Add a service" opens the name and address form. With no saved services, the form shows directly.
5. **Image card and bottom bar:** the bottom bar shows tokens and cost for the session (a provider that reports no cost shows an icon with a hover explanation, not "Unavailable"). The live indicator appears once per surface: in the title bar on desktop, the bottom bar on web.
6. **SPOTTER:** in the composer's approval menu, SPOTTER either arms (a "SPOTTER AI, watching" entry appears in the tasks tray) or is greyed out with a hover saying what to enable (e.g. Flowcept not configured). Clickable-but-broken is a failure.
7. **Add to chat and More details:** select text in an agent answer. A toolbar appears.
   - **Add to chat** quotes the text into the composer.
   - **More details** opens a read-only side panel that answers about the passage, and closing it removes it.
   - Selection in tool cards is not expected yet (#1525).
8. **Long shell output:** ask the agent to run a command with very long output. The tool card shows "Full output saved" with **Open full output**, which opens the file.
9. **Agent questions:** trigger a clarifying question.
   - It appears as a card in the transcript, with a notice above the composer while pending.
   - Answering through "Other" uses the main composer, including an attachment.
   - Chatting is not blocked while it is pending.
10. **External image:** ask the agent to show an image from a public website (this machine has internet). It downloads the image into the workspace and the image renders from the local copy.

## 4. Remote CLIO on ares (needs the owner for password and Duo)

1. From the desktop, **deploy CLIO to the ares login node**. The owner enters the password and Duo when asked; you do everything else. The remote installs clio-agent 0.9.4.20 from PyPI. Screenshot each deploy stage.
2. Then deploy **through the hop to a compute node**. Add the compute node as a hop after the login node. If it needs an allocation, the owner or you allocate one explicitly, and note the job id to cancel later.
3. On the remote CLIO:
   - an agent turn that plots a CSV emits an **A2UI plot** that renders, plus an **artifact card** that opens;
   - an external image renders after the agent downloads it (if ares has internet).
4. **Managed llama.cpp** on the remote, with a tiny model: it shows **protected** with a key; toggling **Shareable** shows the unprotected state; **Uninstall** removes it.
5. **Clean up:** uninstall the remote deployment from the desktop, cancel any Slurm allocation, and confirm on ares (ask the owner to run `ps -u $USER | grep -i clio` and `squeue -u $USER` if you have no shell there) that nothing is left.

## Out of scope

Replying to collaborators on their GitHub issues is the owner's. Selection actions on tool calls and intermediate turns (#1525) come after this release.
