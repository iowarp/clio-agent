CLIO v0.9.5-beta.5.2 fixes fresh Windows Desktop setup failing while preparing Node.js document packages.

### Windows runtime setup

The installer now passes ordinary Windows drive and network paths to Node.js, including when Windows launched bundled Python with a verbatim path. Runtime unpacking, Python packages, pnpm, document packages, Office and the GitHub tool report separate stages in the installer details.

## Fixed

- Fresh Node/pnpm setup no longer fails with `EISDIR: illegal operation on a directory, lstat 'C:'` because of a Windows verbatim path.
- The previous Windows Office extraction fix is retained.

## Beta qualification

This urgent hotfix uses a fresh isolated setup through the actual bundled Windows Python as its immediate acceptance check. Broader source CI and macOS packaged startup qualification run separately under the explicit beta exception; their pending state does not establish acceptance. Windows installer assets and signed updater manifests must be built and verified before publication.

Beta.5 and beta.5.1 were withdrawn from the GitHub release feed after installer failures. Users already on beta.5 should install this hotfix manually because that older update picker cannot recognize hotfix tags. Private configuration, credentials and session data are retained.

See the [CHANGELOG](https://github.com/iowarp/clio-agent/blob/v0.9.5-beta.5.2/CHANGELOG.md) for the complete change history.

```sh
uv tool install --python 3.13 'clio-agent==0.9.5b5.post2'
```
