This beta brings the new CLIO interface, a macOS app signed with Apple's Developer ID
and notarized, a first run that works on a clean Mac, faster desktop installs on every
platform, scripts and live data streams for the agent, and a new Google Drive sign-in.

## Before you upgrade

Data saved by 0.9.5.1 or older does not open in this release. Conversations, memory and
artifacts from that version stay on disk but do not show. The installer detects the old
store and offers to move it aside; nothing is deleted, and your workspace files are not
affected. `clio store-check` says which version wrote your data, and `clio reset-store`
moves it aside when you upgrade without the installer.

Google Drive sign-in moved to a new Google client, so you may need to sign in to Drive
again after upgrading. Until Google finishes verifying the new client, only accounts the
CLIO team has added can sign in. If yours is refused, ask your CLIO contact to add it.

The default port is now 17800 (it was 8100). Update bookmarks, scripts and firewall rules
that use `localhost:8100`, or keep the old port with `gact.port` in your CLIO config or
`--port`. (#1966)

CLIO Desktop for macOS now requires macOS 15 or newer.

### New interface

This beta ships the new CLIO interface for Desktop and Web. (#2030, #2036)

### A signed and notarized macOS app

The macOS app, its helper and every program in its bundled runtime are signed with
CLIO's Developer ID and notarized by Apple, so a downloaded app opens without an "Open
Anyway" step and can be shared directly. Running CLIO no longer writes into the app,
which used to break its signature after the first launch. (#1978, #1966)

### CLIO runs on a clean Mac

CLIO no longer needs Xcode's Command Line Tools. It ships its own git, uses yours when you
have one, and never runs the placeholders that open the "Install Command Line Developer
Tools" dialog. `clio start` no longer depends on `setsid`, and a fresh store is no longer
mistaken for the old format and refused at startup. (#1964, #1966)

### Faster desktop installs

The desktop installers for macOS, Windows and Linux share the same steps: they download
the app as one archive, unpack it while it downloads, and prepare it while the signature
check runs. The bundled runtime ships fewer files and starts without recompiling its
modules. (#1985, #1987, #2000, #2021, #2034)

### Scripts and live data streams

The agent can write a Python script that calls its own tools and reads only what the
script prints. Running a script is one approval. A script can run in the background,
report its progress and keep running after the turn ends. Streams keep a live table that
views and dashboards read while it grows, saved as versions in the workspace. (#1924)

### Long conversations stay on track

The agent keeps a session plan you can see and edit in the Work panel. It loads rarely
used tools only when it needs them, and after a conversation is compacted it can recall
the earlier steps the summary replaced. Reminders can be reviewed, edited and switched
off under Settings. (#1924)

### Open HDF5 files in the workspace

The file viewer opens HDF5 files from your workspace, reading only the slices it shows.
(#1834, #1910)

### Move a conversation to another workspace

A conversation can move to another workspace with its delegated work and tool output.
(#2014)

### Provider support installs without a restart

Installing Claude Code or another provider from the provider picker runs as a background
job and works right away, including from the signed app, without restarting CLIO. (#1980,
#1984, #2023)

### Workflows run steps as soon as they are ready

A workflow starts each step as soon as the steps it depends on have finished, and
combines their results in the order the workflow defines them. (#1926)

## Fixed

- CLIO's runtime log can no longer fill the disk. It is capped with one rotated copy,
  repeated lines are collapsed, and a runaway log shows in `clio-agent doctor` and
  `/v1/health`. The underlying loop is tracked in iowarp/clio-core#1353. (#1983)
- CLIO's store accepts connections only from this computer. (#1966, #2037, #2040)
- The app waits until CLIO is ready instead of showing errors while it starts. (#1966)
- Web search and the other bundled tools work from the app without first running the
  command line installer, and a failed first web search setup retries. (#1976, #2007)
- The first browser action on a new install says the browser is downloading instead of
  timing out. (#1977)
- Google Docs, Sheets and Slides show "unknown until read" instead of "0 bytes", and
  linking a Drive folder while a conversation runs no longer fails its first tool calls.
  (#1982)
- NDP agents can search the data catalog before you attach a source, and CLIO no longer
  points at an NDP backend that stopped answering. (#1990, #1996,
  iowarp/clio-agent-marketplace#127)
- Exporting a session with its workspace files no longer fails on one unreadable file or
  a long Windows path; anything that cannot be read is listed in the export. (#1993)
- Quitting CLIO no longer hangs while its store stops. (#2028)
- On Windows, scripts can import numpy, first run works from a deeply nested home folder,
  and the server keeps listening when a client disconnects early. (#2001, #2009, #2010)
- A long-running CLIO no longer keeps an exited background process each time its store
  restarts. (#1989)

## Changed

- Google Drive uses a new Google sign-in client. (#1981)
- The sandbox that confines the agent's commands is active on macOS and Linux app
  installs, where it was silently off. (#1966)
- Uninstalling can remove the runtime CLIO downloaded, its caches and its data. (#1966)
- Permission questions wait until they are answered instead of expiring after ten
  minutes.
- The website has a final privacy policy and terms of service. (#1969, #1988)

## Breaking

Data saved by 0.9.5.1 or older must be moved aside, as described above. The default port
moved from 8100 to 17800. (#1966)

## Known issues

- On a fresh install with no conversations yet, attaching a newly connected Drive folder
  stops at "Choose a conversation to track this work". Start a conversation first.
  ([iowarp/gact-tui#873](https://github.com/iowarp/gact-tui/issues/873))
