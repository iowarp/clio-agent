This is the fifth hotfix for the v0.9.6-beta.1 beta. It keeps Linux installs working while Launchpad and snapshot.ubuntu.com are unreachable, and makes the one-line install on Windows and Apple silicon Macs much faster by using the release's prebuilt runtime. Everything in [v0.9.6-beta.1.4](https://github.com/iowarp/clio-agent/releases/tag/v0.9.6-beta.1.4) is included.

### Linux installs work during today's Ubuntu outages

Launchpad and snapshot.ubuntu.com stopped answering today, so every Linux install failed while fetching LibreOffice's supporting packages. These now come from archive.ubuntu.com (x64) and ports.ubuntu.com (arm64), which are still up. The four amd64 packages that only the older hosts carried move to their current Ubuntu security builds. The older hosts remain as fallbacks, and every file is still checked against its pinned checksum (#2115).

### Faster one-line install on Windows and Apple silicon

Without the desktop option, the one-line install used to resolve and install about 300 packages from PyPI. On Windows (x64) and on Apple silicon Macs with macOS 15 or later, it now downloads the release's prebuilt agent runtime and unpacks it while the download runs. Releases without that runtime still install from PyPI, and you can ask for the old path with `CLIO_INSTALL_FROM=pypi` (#2109, #2110).

## Fixed

- A plain macOS install no longer opens the "Install Command Line Developer Tools" dialog on a Mac without them (#2106), and no longer stops silently when a release has no macOS checksums (#2111).
- `clio uninstall` also removes the uv, uvx and clio-kit that the installer added (#2112).
- After `clio update`, preparing documents no longer fails because the bundled document packages were built for the previous release (#2113).
- `clio stop` also stops the local services CLIO started, such as web search, so an upgrade can replace the installed environment (#2114).
