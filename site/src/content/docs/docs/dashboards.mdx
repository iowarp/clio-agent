A dashboard brings an analysis into one interactive report beside the
conversation. Ask the agent to decide what belongs together: explain the main
finding, compare selected results, remove repeated views, and keep the supporting
data accessible. It can combine text, metrics, charts, maps, tables, images, and
3D views using the same [widget components](/docs/widgets/components/).

</Aside>

## Ask the agent to compose the report

```text
Build a dashboard from these station counts. Explain when Fernhill first runs
empty and compare the net change by area. Keep the time chart, station comparisons, map and exact evidence together. Keep time, capacity and units visible, use consistent area
colours, and distinguish dock counts from trips.
```

This is an authoring task. The agent reads relevant earlier outputs and their
data, chooses a structure, and can add a new figure or explanation when it helps
answer the question. You can also specify which views to keep or omit.

The dashboard opens with its authored title and dashboard icon in the side panel. Follow-up requests revise
that report over multiple tool calls; it does not have to fit in a single widget
generation or a pair of graphs.

## Explore one connected system

| Element         | What to ask for                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------------- |
| Overview        | The finding, a few key measures, and the scope of the data.                                         |
| Composed rows   | Give the main chart twice the width of its comparison, then use equal panels for the map and table. |
| Optional depth  | Use tabs for separate workflows or detailed evidence after the main comparison.                     |
| Shared controls | One filter or selected entity driving the relevant views.                                           |
| Linked views    | Highlight the same records across a map, chart, or table.                                           |
| Explanations    | Units, definitions, captions, limitations, and why a view matters.                                  |
| Optional detail | A readable default with additional series or sections you can reveal.                               |

Views only move together when their controls and data are connected. Two plots
on the same page do not automatically share filters, and paired 3D views need a
shared camera binding to rotate together. See [Linked data](/docs/widgets/linked-data/).

The report is also a place to continue investigating. Select a station to
highlight its matching chart, map and table records, reference that evidence in
the conversation, and ask CLIO to explain or revise it. The agent can inspect
the same rendered view and recheck a correction. **Versions** and **Lineage**
retain the report's earlier states and inputs while the conversation presents
the latest deliverable.

## Arrange the evidence deliberately

Ask for a wide chart next to a smaller supporting comparison, then two equal
panels in the next row. CLIO uses the existing relative layout weights: 2:1
above and 1.5:1.5 below. Expanded reports retain those proportions; a narrow
side panel stacks analytical rows to keep labels readable.

Put images beside the measurements and text that explain them. For a research
report, material images and parameters can sit beside linked 3D views and
result distributions. Keep controls close to the views they affect and retain
the same object identifiers across a viewport, chart and table.

Tabs remain useful for independent workflows and optional depth. The central
comparison should be visible together when you first open or export the report.

## Point to a part and revise it

<Steps>

1. Open the dashboard and find the relevant view.

2. Select records and use **Reference this**, or use **Capture labelled regions**
   to attach a visual area to the next message.

3. Give a concrete request: “Explain this cluster,” “Show the original only once,”
   or “Hide the minor series by default and let me turn them on.”

4. Open the revised artifact. **Versions** keeps earlier reports;
   **Lineage** shows the inputs and steps behind them.

</Steps>

The reference carries the selected data or visual context, so you do not need
to describe a location from memory. The same interaction is demonstrated in
[Human-agent interaction](/docs/widgets/interaction/).

## The agent checks its presentation

The dashboard and visual-review skills instruct CLIO to inspect the rendered
overview and relevant tabs before presenting a substantial report. It can
change declared filters, tabs and cameras, receive the matching screenshot as
image input, and correct an unclear view. A newly published report opens in
the currently viewed conversation so the agent can check that version.

You can also request another pass with a specific concern:

```text
Check this dashboard at side-panel size. Inspect each tab for clipped labels,
overlapping legends, and too many visible series. Fix unclear views, keep the
underlying data, and recheck the result before presenting the final version.
```

The check follows controls the view actually exposes. Hidden tabs need to be
selected before capture. If the conversation is not open or no viewer can supply
pixels, CLIO should state that limitation. A successful publication only accepts
the definition; it does not prove the agent saw it. Visual review also does not
replace calculations or establish causality from a pattern.

## Read the report before opening every detail

Start with the question, the main finding and a few useful measures. Related
views should carry the same category meanings, units and time interval. Subdued
grids and context marks let the key comparison stand out; a direct annotation
can explain an empty station without making the reader hunt for it.

Keep complementary views visible together so you can compare them and a PNG
contains the main story. Use tabs for separate workflows or optional depth;
use selectors for additional series instead of drawing every series at once. Keep the complete evidence accessible and state the
initial slice. In this example, the total remains 54 bikes at every snapshot;
matching area changes do not identify individual journeys or missed trips.

## Download an image or an interactive report

Use the dashboard's **PNG** action for an image of the displayed view. Use **HTML**
for a self-contained report with its tabs, supported interactions, and referenced
data bundled. Dependencies that cannot be captured are reported rather than
quietly left out. A saved report cannot call a live agent on its own.
Offline maps keep included points and geometry; external basemap tiles are not
bundled.

If the dashboard belongs to a larger investigation, [export the session](/docs/exports/)
with its artifacts to retain the conversation and evidence alongside it.
