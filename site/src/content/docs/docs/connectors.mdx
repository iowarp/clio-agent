A connector is a service you enable for the agent: a molecule viewer, ParaView, a
circuit simulator. It has a logo, it says what it needs from you, such as an address
or a sign-in, and you give it those things on one card. Enabling it installs it and
gets it ready; it does not put it in any conversation. You add it to the
conversations that need it, so a conversation that does not use ParaView never
carries ParaView's tools. Many connectors also show their results as a live
[app](/docs/apps/) in the conversation or in a tab.

## Enable a connector

<Steps>

1. Open **Settings → Extensions**. Connectors are listed first, each with its logo
   and its state in words. Choose **Connectors** above the list to see only them.

2. Choose a connector. Its card opens beside the list.

3. Fill in any rows under **Setup**, then choose **Save**. CLIO connects, lists the
   connector's tools and updates its state.

4. Under **In conversations**, choose **Enable**. CLIO starts it, lists its tools and
   shows **Ready** with the number of tools.

</Steps>

A connector's state reads the same everywhere it appears:

| State | Meaning |
|---|---|
| **Ready, 4 tools** | It answered and its tools are available. |
| **Needs** followed by what, such as **Needs a sign-in** | A required row is empty. Optional rows never hold a connector back. |
| **Can’t be reached** | CLIO started or called it and it did not answer. The card gives the reason, for example that nothing answered at the address. |
| **Not enabled** | It is turned off. |

**Turn off** stops it. A conversation you added it to keeps it in its list but cannot
use it, and says it left because the connector is turned off; enable the connector
again and it is back in that conversation. Its values and secrets are kept, so
enabling it again needs nothing more.

## Add a connector to a conversation

In the conversation, open the **Agent** tab and choose **Add plugin**. Enabled
connectors are listed first, under **Connectors**, with their logos and their state.
Choose one. Its tools join this conversation only; other conversations are not
changed. In a conversation that has already started, CLIO asks how the change reaches
the agent, as for any plugin, and the conversation shows that its plugins changed.

The connector then reads **Connector you added** in the agent's list. Remove it there
to take it out of this conversation. A connector that is turned off is not offered;
enable it in Extensions first, or let the agent offer it (below).

To have a connector in every new conversation of an agent, add it to that agent: open
the agent in **Settings → Agents**, or save a conversation's setup as an agent.

## The setup card

Each row of the card is one thing the connector needs:

- **Address** or **value**: a text field, or a list to pick from. Some rows say
  **The agent can set this**.
- **Secret**: a masked field, for a token or a key. After you save it, the field
  stays empty and says **Saved. Type a new one to replace it**. Leaving it empty
  keeps the saved secret.
- **Sign-in**: a **Sign in** button that opens the service's own sign-in page. The
  row then reads **Signed in** or **Not signed in**.

Rows marked **Required** must be filled before the connector is ready.

When you change a value, CLIO reconnects to the service, or restarts it if it runs on
your machine, and lists its tools again.

### Values for one conversation, and defaults

*Amended.* The values in Extensions are your **defaults**: every conversation uses
them unless it has its own. A value given inside a conversation, by you on a card or
by the agent, is that **conversation's own**. Pointing ParaView at node08 in one
conversation leaves another conversation's ParaView on this machine, and the views
in both stay open.

On a card in a conversation, each address or value row has **Save as default**.
Leave it clear to keep the value in this conversation only; the row then reads
**This conversation only** and shows the default it replaces. Tick it to make the
value your default for new conversations too. Secrets and sign-ins are always yours
for every conversation.

A conversation with values of its own gets its own copy of the connector's server, so
it never changes what another conversation is connected to. Reopening a view in a
conversation uses that conversation's values.

A secret goes to the service only. It is kept in CLIO's credential file in your
configuration folder, readable only by you, and never appears in the conversation,
in what the model reads, or in the logs.

## When the agent needs a connector that is not ready

If the agent calls a tool of a connector that still needs something, the call waits
and a setup card appears in the conversation. It names the tool that is waiting and
shows only the missing rows.

- Fill them in, or sign in, and choose **Continue**. The same call then runs and
  returns its result. You do not need to ask again. A card that needs only a sign-in
  continues by itself once you have signed in.
- Choose **Decline**, or press Esc, to refuse. The call returns a refusal that names
  the connector, and the agent tells you it could not use it.
- Stopping the reply also ends the waiting call.

## What the agent can change

Some values are things you might say in passing: "the ParaView I want is on node08".
A row marked **The agent can set this** can be changed by the agent with its
`set_connector_value` tool. It can set several values of one connector in one call,
and the card shows the new values. *Amended:* the agent sets them for the
conversation it is in, never as your defaults; its step reads **Applies to: This
conversation**. The call follows your
[permissions](/docs/permissions/) like any other tool.

The agent can never set a secret or sign in for you. It cannot change a row that is
not marked, and it cannot turn a connector on or off.

## When the agent offers a connector

If you ask for something a connector does and the conversation does not have it, the
agent can offer it: a card reads **Add ParaView to this conversation?**, with the
connector's logo and whether it is enabled, then the agent's reason on one line (select
it to read all of it). Anything the connector requires shows below; its optional
settings wait behind **Settings** next to the buttons. Choose **Add** and the connector
joins this conversation, enabled first if it was off, and the agent continues your
request in the same reply. Choose **Not now** and nothing changes. The agent never adds
a connector by itself.

The agent offers any plugin you have the same way, not only a connector's: it knows
the plugins and connectors this conversation does not have, each with a line about
what it does and the marketplace it comes from, and offers one when your request needs
it. A plugin's card reads **Add tariff-calc to this conversation?** and says which
marketplace it comes from; after **Add**, its skills and tools are the agent's in the
same reply. See [Agents and plugins](/docs/agents-and-plugins/).

## Plugins that come with a connector

A connector can bring a plugin, such as instructions for working with its tools. The
card names it under **Brings plugin**. You do not install it yourself: adding the
connector to a conversation adds its plugin, which is listed under the connector's
name. In the Extensions list the plugin is shown with its connector, not on its own.

## Add a service by URL or command

For a service that has no connector, choose **Add → Add by URL or command** in
Extensions. Give it a name and either the address of a remote MCP server or a local
command with its arguments.

CLIO adds it as a connector with a monogram. Its card shows the address, and a
**Sign in** row when the service asks for one. **Remove** deletes a connector you
added this way.

Anything under the form's advanced settings, such as request headers, an
authentication mode or environment variables, makes it a plain MCP connection
instead. See [Connect tools and services](/docs/mcp-servers/).

## Connectors CLIO includes

### Burette

[Burette](https://github.com/SergeiNikolenko/Burette) shows molecular structures from
the Protein Data Bank in Mol*, and draws or edits molecules in Ketcher. It is a hosted
service and needs nothing from you. Ask, for example, "Show PDB 1CRN". CLIO offers its
PDB-ID and Ketcher tools; its file tools need another host's file attachments and are
left out.

Burette's viewer draws nothing in a frame 600 pixels wide or narrower, which includes
a phone and a narrow side panel. Widen or maximize the panel. See
[Apps](/docs/apps/#known-limits).

### SPICE circuit simulation

Runs [ltspice-mcp](https://github.com/cognitohazard/ltspice-mcp) 0.8.0 on your machine
through `uvx`, and plots waveforms in the conversation. Install ngspice, or LTspice on
Windows, first. It does not support macOS. Ask, for example, "Simulate rc_lowpass.cir
with ngspice and show me V(out)".

### 3D globe

Runs the [MCP Apps map example server](https://github.com/modelcontextprotocol/ext-apps/tree/main/examples/map-server)
(`@modelcontextprotocol/server-map` 2.0.4) on your machine through `npx`, and shows a
region on a 3D globe you can turn and zoom, in the conversation or in a tab. It needs
Node.js 20 or later and nothing from you. The globe is drawn with CesiumJS, loaded from
cesium.com, over OpenStreetMap tiles, and it finds places by name with OpenStreetMap's
Nominatim. Ask, for example, "Show me the Cascadia subduction zone on a 3D globe". With
NASA Earthdata in the same conversation, the agent can search for datasets and then
show the area the search covers.

The globe frames a region and labels it. It does not draw points, outlines or GeoJSON,
and it does not zoom closer than about 500 km above the ground.

### PDF viewer

Runs the [MCP Apps PDF example server](https://github.com/modelcontextprotocol/ext-apps/tree/main/examples/pdf-server)
(`@modelcontextprotocol/server-pdf` 2.0.4) on your machine through `npx`, and shows a
paper in a viewer you can page through, search and zoom, in the conversation or in a
tab. It needs Node.js 20 or later and nothing from you. It opens papers by address
from arXiv, bioRxiv, medRxiv, ChemRxiv, Zenodo, OSF, HAL and similar archives. Ask,
for example, "Show me arXiv 2611.15421 so I can read it". The agent reads the page you
are on, can jump to a section, search the paper and take a picture of a page.

It cannot open a file from your workspace yet. Each time the viewer opens, it reads the
whole file again, and the conversation keeps a row for every part it reads.

### NASA Earthdata

Runs [earthdata-mcp-server](https://github.com/datalayer/earthdata-mcp-server) 0.6.0 on
your machine through `uvx`. It searches NASA's Earthdata catalog for Earth-science
datasets and their files, for example "Which GRACE-FO terrestrial water storage
datasets on NASA Earthdata cover 2020 to 2024?". Searching needs no account. To
download files, enter your free
[NASA Earthdata Login](https://urs.earthdata.nasa.gov) username and password in its
two optional rows.

| Row | What to enter |
| --- | --- |
| **Earthdata Login username** | Empty to search only. |
| **Earthdata Login password** | Kept as a secret. Never shown again once saved. |

### ParaView

Opens scientific data in ParaView and shows it in a live view the agent can drive. It
needs ParaView 6.0 or later where ParaView runs. All three rows are optional, and the
agent can set each:

| Row | What to enter |
|---|---|
| **Where ParaView runs** | Empty for this machine. Otherwise an SSH host name, including an alias from your `~/.ssh/config`. |
| **Jump host** | A host to go through, when your SSH configuration does not already give one. |
| **Command to run first** | A line that puts `pvpython` on the path, for example `module load paraview`. |

On this machine, CLIO looks for `pvpython` after running the first command. If there
is none, the first scene request says so and tells the agent how to point the
connector at another machine.

#### ParaView on another machine

Two hops such as `ssh login` then `ssh node08` are one setting: **Where ParaView runs**
`node08`, **Jump host** `login`. You can also just tell the agent: "Connect to the
ParaView on node08, through login. It needs `module load paraview` first."

- CLIO uses your own `ssh`, keys, agent and `~/.ssh/config`, over one connection.
  Nothing listens on the network on either side.
- The first time on a machine takes a minute or two. CLIO prepares a folder,
  `~/.clio/paraview/<version>/`, with what the view needs. If that machine cannot
  reach the Python package index, it builds the folder from the jump host, which
  shares your home folder on most clusters. Later connections reuse it and take
  seconds.
- If a ParaView server (`pvserver`) is already running on that machine on port 11111,
  the view joins it and shows that session's data.
- File paths are paths on the machine where ParaView runs.
- If the connection drops, the scene is kept there and the next request reconnects.
  With no connection for 30 minutes, ParaView on that machine saves the scene and
  stops.

<Aside type="caution" title="Key-based SSH only">
A host that asks for a password or a one-time code on every connection does not work.
The first request fails at once with a message that interactive sign-in is needed.
Use an SSH key or agent that the host accepts.
</Aside>
