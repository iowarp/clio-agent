A stream is a way to deliver measurements. It does not establish when those
measurements were acquired. Start with the scientific question and inspect the
measurement timestamps before calling a result live.

## Choose the data you need

| Source | Useful for | What CLIO retains |
| --- | --- | --- |
| A published dataset file | Historical analysis over its documented coverage | The selected original and separate analysis outputs |
| Archived CSV replay | Processing historical observations incrementally | Finite SSE captures, measurement timestamps and a resume cursor when supplied |
| An Endpoint service query | A filtered scientific response, such as station metadata | The response bytes and query provenance |
| A live bridge or producer | Forwarding current upstream observations to a destination topic | Producer identity/status and separately captured observations |

Station metadata describes an instrument and its location or operating epochs.
It is not a displacement, waveform or water-level time series. A successfully
started producer is also not evidence that CLIO has received measurements.

## Capture a finite segment

Connect the existing service from **Attach → National Data Platform → Endpoints &
streams** using its URL or a saved SSH profile. Use the service's Files, Stations
or Streams view as available. Review the selected resource/station and limits,
then save a sample. Opening a saved connection does not start a producer.

For an archived CSV, choose **Files → Sample CSV from URL**, paste the published
file address and choose **Rows to sample**. Open **Options** to set the delivery
interval or continue from a previous sample. Choose **Save sample**.

The capture becomes an ordinary file in **Sources**. Its receipt records the
Endpoint, operation, filters, capture times, status, byte count, SHA-256 and stop
reason. The agent can read these same bytes and create a chart or report.

Default limits are **10 seconds and 100 SSE events**. Maximum limits are
**30 seconds, 1,000 events and 2 MiB**. These are capture bounds, not a promise of
that many observations. For example, `hello`, heartbeat and `done` messages count
as events but are not scientific samples. A byte or time limit may leave a final
event incomplete; preserve that fact rather than counting it as a complete row.

## Resume without duplicating observations

When an API returns a resume value, pass the exact value to its advertised cursor
parameter. Inspect its response schema: the EarthScope replay service returns a
`done` event containing **`resume`** and **`next_index`**, while the next request's
parameter is named **`cursor`**. An SSE event ID is not necessarily a cursor.

Check sample identities or measurement timestamps across adjacent segments for
duplicates and gaps. Record the selected resource revision/hash as well as the
cursor. A missing completion event does not establish a safe resume point.

An observed replay on October 18, 2026 returned three records followed by two
more, with measurement times **December 3, 2024, 00:00:00–00:00:04 UTC**. That is
archived replay, despite being delivered through a stream today.

## Own the producer you start

A live bridge can register a derived dataset and forward an upstream topic.
Inspect its actual station/topic catalog and existing sessions first. Keep the
returned session ID, destination and any registration IDs. Inspect status and
obtain actual observations before claiming live data access.

Closing CLIO's capture closes its HTTP/SSH reader. It does **not** stop a remote
producer. Stop the specific producer started for your investigation and check
its terminal state. Do not stop unrelated sessions. If a start request times out,
inspect session state before retrying; a lost response does not prove no work began.

## Check what the sample contains

Open the saved capture and check its measurement timestamps, units and coverage
before interpreting it. A successful connection or a station listing is not a
measurement result. Historical observations remain historical even when the
service delivers them incrementally.

If a sample contains only status messages, it does not yet support a scientific
comparison. Keep the capture and its receipt with the investigation so that you
can distinguish the requested observations from the bytes actually received.
